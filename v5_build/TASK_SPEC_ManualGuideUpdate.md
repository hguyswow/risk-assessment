## 1. Context (왜 필요한가)

INCIDENT-1 복구 이후 사용자가 실제 앱을 확인해보니(매뉴얼 모드는 정상 작동, 버전이 "6.0"으로 표기됨을 확인) 두 가지를 요청했다:
1. 이번 세션에서 새로 만든 두 기능(WO-1 매뉴얼 모드, WO-2 표 여백 조절)이 사용자 가이드(`manual.html`)에 전혀 문서화되어 있지 않으므로 추가할 것.
2. "혹시 모를 에러"가 있는지 점검할 것.

에러 점검(감독모드가 이미 수행 완료, 결과는 아래 2.3 참고) 결과 코드 자체의 문법/참조 오류는 0건이었으나, **버전 표기가 파일마다 제각각**인 것이 확인되어 이번 작업 범위에 함께 포함한다.

사용자 확정 답변(질문 결과):
- 새 기능 2개 문서화: **확정**
- 버전 표기: **실제 코드와 일치시키기** (index.html의 실제 `APP_VERSION`을 기준으로 `package.json`/`manual.html` 표기를 전부 하나의 값으로 통일)
- 자동업데이트 다운로드/설치 기능(현재 `main.js`에는 핸들러가 있으나 `index.html`에서 호출하지 않는 상태) 복구: **이번 범위에서 보류** — 절대 손대지 말 것

### 2.2 버전 번호 결정 (권장안 — Gemini는 착수 전 의견 보고서에 동의 여부를 명시할 것)
`index.html`(6.0.0) / `package.json`(6.0.1) / `manual.html`(v6.0b, 실질적으로 다른 라벨) 셋 다 서로 다르다. 이번에 신규 기능 2개(매뉴얼 모드, 표 여백 조절)를 얹으면서 자동업데이트 배너 등 일부 옛 기능은 빠진 상태이므로, 기존 "6.0.1"을 그대로 재사용하면 실제로는 그 시점과 다른 기능 구성인데 같은 번호를 참칭하게 되어 오해를 유발한다.
**권장: `6.0.2`로 통일.** (6.0.1보다 높은 새 번호로, "복구된 6.0.0 베이스 + 이미 존재하는 법령인용 금지 패치 + 이번 세션의 신규 기능 2종"을 정직하게 반영. 자동업데이트 다운로드 배너 등 일부 기능이 없다는 사실 자체는 버전 번호가 아니라 가이드 본문에서 굳이 언급하지 않아도 됨 — 없는 기능을 가이드에 적지만 않으면 됨.)

변경 대상:
- `package.json:3` `"version": "6.0.1"` → `"6.0.2"`
- `index.html:4117` `const APP_VERSION = "6.0.0";` → `"6.0.2"`
- `index.html:3723` `<strong>v6.0.0</strong>` → `<strong>v6.0.2</strong>`
- `manual.html`의 모든 `v6.0b` 문자열(2.1에 나열한 6곳) → `v6.0.2`

### 2.3 감독모드 사전 에러 점검 결과 (참고용 — 이번 작업과 별개로 이미 완료됨)

## 3. 구체적인 구현 방법

### A. 버전 번호 통일
2.2에 나열된 모든 위치를 `6.0.2`로 일괄 변경. `index.html:3723`은 먼저 하드코딩 문자열인지 `APP_VERSION` 변수 바인딩인지 확인 후, 하드코딩이면 문자열 치환, 바인딩이면 자동 반영되므로 손대지 않음.

### B. STEP 3-1. 🛠️ 매뉴얼 모드 섹션 신규 작성 (manual.html, STEP 3 다음)
다음 내용을 포함해 STEP 2-1/2-2와 동일한 스타일로 작성:
- 매뉴얼 모드란 무엇인지(편집화면 상단 "🛠️ 매뉴얼 모드" 토글로 켜고 끔), 왜 쓰는지(초보자가 기존 DB 구조를 깨지 않고 새 항목을 직관적으로 추가할 수 있게 하기 위함).
- 켜면 나타나는 두 가지:
  1. `➕ 새 항목 추가 (매뉴얼)` 버튼 → 4단계 마법사(공종 선택/입력 → 세부작업명 선택/입력 → 위험세부분류 선택/입력 → 유해위험요인·현재조치·개선대책·위험도 입력) → 확인 시 기존 DB 구조에 자연스럽게 편입되어 편집화면과 화면1 트리 양쪽에 즉시 반영·영구 저장됨을 설명.
  2. 유해위험요인/개선대책 셀 옆 ⚙️ 아이콘 → 행(항목) 단위로 AI 생성 디테일(간결/보통/상세)과 최대 글자수를 개별 지정할 수 있음을 설명. 전역 AI 설정과 다르게 이 행만 적용됨을 명시.
- TASK_SPEC_ManualMode.md의 실제 구현 내용과 정확히 일치하는 설명만 작성할 것(구현되지 않은 것을 적지 말 것 — 예: 리셋 버튼, 프리셋 버튼은 백로그(SB-1, SB-3)로 아직 없음, 가이드에 언급 금지).

### C. STEP 5-2. 📏 표 여백 조절 섹션 신규 작성 (manual.html, STEP 5-1 다음)
다음 내용을 포함해 STEP 5-1과 동일한 스타일(초록 계열 `border-left: 5px solid #22c55e;` 또는 유사 톤)로 작성:
- 최종 보고서 미리보기 화면 액션바의 "📏 표 여백" 패널(줄수 입력, 행높이(px) 입력) 위치와 용도 설명.
- 항목 수가 적을 때 표 하단에 남는 빈 공간을 줄수를 낮추거나 행높이를 조절해 인쇄물 여백을 사용자 취향대로 맞출 수 있음을 설명.
- 정석형/세련형/미래형 3개 인쇄 테마 모두에 공통으로 적용됨을 명시.
- 값 범위(줄수 6~24, 행높이 15~45px)와 변경 즉시 미리보기에 반영됨을 언급.
- TASK_SPEC_ReportRowHeight.md의 실제 구현과 정확히 일치하는 내용만 작성(리셋 버튼·프리셋 버튼은 백로그 SB-4/SB-3로 아직 없음, 언급 금지).

## 4. Red Team 체크포인트

1. **버전 번호 3파일(`package.json`, `index.html`, `manual.html`) 전부 빠짐없이 `6.0.2`로 통일했는가?** 하나라도 누락하면 이번 작업의 목적 자체가 무색해진다.
2. **`download-update`/`execute-installer` 관련 코드는 이번 작업에서 절대 건드리지 않았는가?** (사용자가 명시적으로 보류를 선택함 — 이 부분을 "복구"하거나 "가이드에 언급"하는 것 둘 다 범위 밖.)
3. 신규 가이드 섹션에 **실제로 구현되지 않은 기능(리셋 버튼, 프리셋 버튼 등 SB-1/SB-3/SB-4 백로그)을 적지 않았는가?** 사용자가 가이드만 보고 없는 버튼을 찾아 헤매게 되는 걸 방지해야 함.
4. 기존 `[기존 코드 백업]` 주석 컨벤션을 유지했는가 — 버전 문자열을 바꿀 때 기존 텍스트를 그냥 지우지 말고, 이 프로젝트 관행대로 이전 값을 주석으로 보존하고 새 값을 활성 코드로 둘 것(단, 매번 그럴 필요는 없음 — 이미 v5.5.21b→v6.0b 이력이 주석으로 충분히 쌓여있으므로, 이번 v6.0b→v6.0.2 변경분만 새로 주석 보존하면 됨. 과도하게 모든 줄마다 주석을 겹겹이 쌓지 말 것).
5. `manual.html`의 새 섹션이 기존 스타일(`step-box`, 색상 톤, 이모지 컨벤션)과 시각적으로 이질감 없이 통일되어 있는가?
6. 문자열 치환 시 `v6.0.0`이나 `6.0.1` 같은 부분 문자열을 의도치 않게 다른 무관한 곳(예: 주석 처리된 이력 백업 줄, 다른 버전 넘버링 문맥)까지 잘못 바꾸지 않았는가 — 정확히 2.1에 나열된 위치만 수정할 것.

## 5. 검증 절차

1. 정적 검증: `node -c aiService.js`, `node -c main.js`, index.html 스크립트 블록 파싱, `package.json` JSON 파싱 — 전부 재실행해 오류 0건 확인.
2. `grep -rn "v6.0b\|6\.0\.0\|6\.0\.1" manual.html package.json index.html`로 남은 구버전 표기가 없는지(단, 주석 처리된 이력용 백업 줄은 제외) 확인.
3. `npm start`로 앱을 직접 띄워 스플래시/AI 설정 패널의 버전 표시가 `6.0.2`로 보이는지 확인(가능한 환경에서).
4. `manual.html`을 브라우저로 열어 새 STEP 3-1, STEP 5-2 섹션이 올바른 위치에, 깨진 마크업 없이 렌더링되는지 육안 확인.
5. 위 확인이 전부 끝난 뒤에만 `WORK_ORDER_master.md`에 WO-3로 기록하고 완료 처리.
